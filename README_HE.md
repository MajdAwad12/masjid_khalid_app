# תיקון חסימה לניסיונות עם שמות משתמש שונים

**הוספנו גם חסימת ממשק:** בזמן החסימה שדות שם המשתמש והסיסמה וכפתור הכניסה מושבתים, ומוצגת ספירה לאחור עד לסיום החסימה. הכפתורים "ביטול" ו"שכחת סיסמה" נשארים זמינים, כדי שלא לנעול את אפשרות היציאה והשחזור. משך החסימה נשמר מקומית גם אם סוגרים ופותחים את החלון. שרת Firebase הוא מקור האמת; חסימת הכפתורים לבדה אינה אמצעי אבטחה.

**מה השתנה:** שלושה ניסיונות כושלים מאותה כתובת IP, גם עם שמות משתמש שונים או לא קיימים, יובילו לחסימה של 15 דקות. אם לאחר סיום החסימה מתבצע ניסיון שגוי נוסף, תהיה חסימה של 24 שעות. ההתחברות המוצלחת מאותו מקור מאפסת את הספירה.

**מגבלה חשובה:** כמה אנשים באותה רשת Wi-Fi עשויים לחלוק כתובת IP ולכן גם חסימה. שינוי רשת/IP עוקף הגבלה זו; גם אפשרות התחברות ישירה ל־Firebase Auth אינה נחסמת על ידי מנגנון זה. לכן מדובר בהגנת האפליקציה בלבד, לא מנגנון אבטחה מוחלט. לא נרשמות כתובות IP גולמיות במסד, אלא מזהה hash.

## התקנה

מתיקיית הפרויקט `C:\development\projects\masjid_khalid_app`:

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\masjid_cooldown_all_usernames_fix.zip" -DestinationPath . -Force
dart format lib
flutter analyze
cd functions
npm run lint
cd ..
```

אם הבדיקות תקינות, פרוס *רק* את פונקציית ההתחברות:

```powershell
firebase deploy --project masjid-khalid-app --only functions:loginAdminWithCooldown
```

סגור את האפליקציה והפעל אותה מחדש באמצעות `flutter run` (לא רק hot reload). בדוק שלוש כניסות עם שמות משתמש שונים, תקינים מבחינת UI, וסיסמה שגויה. אל תבחן את חסימת ה־24 שעות על החשבון הראשי. במקרה של רשת משותפת, הבדיקות עשויות לחסום זמנית גם מנהל אחר באותה הרשת.
